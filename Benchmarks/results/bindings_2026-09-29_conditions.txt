Go, Node and R bindings: call overhead (previous commit c4e2f6f against this one) and the chunked
import against concatenating first. 2026-09-29 to 2026-09-30, Apple M4 Max, macOS; Go 1.27.1 and
arrow-go v18.7.0; node v24.9.0 and apache-arrow 21.2.0; R 4.5.3 and arrow 25.0.0. Both builds of
each binding loaded the same libArrowMetalC.dylib (built -c release from this commit; Sources/ is
identical in both commits).

Method. Each block ran only when no other timing or build held the machine and the 1-minute load
average was below 3.5; the load at the start and end of each block and the last sleep entry of
`pmset -g log` are below (no block spans a sleep). Every row: calls of the same shape run untimed
for at least 100 ms, then a 500 ms idle and one call timed on its own (first_after_idle_ms), then
the timed calls (30 per row in the four rounds, 100 in the re-time, 1,000 in the second re-time,
which ran two of its planned eight rounds; 10 in the chunk rounds), giving best and median wall time
and process CPU time per call (getrusage / process.cpuUsage / proc.time). The previous and this
commit alternate in every round, in the order old-new, new-old, ... Programs:
go/arrowmetal/cmd/ambench, go/arrowmetal/cmd/amchunks, node/bench/overhead.mjs,
node/bench/chunks.mjs, r/arrowmetal/inst/bench/overhead.R, r/arrowmetal/inst/bench/chunks.R (with
its `gc` argument for the _gc_between rows).
